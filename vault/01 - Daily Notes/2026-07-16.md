## Session 11 - Evening: NSSM Service Migration (VBSquote-bug fix)

### What Got Done
- Diagnosed root cause of 2-day bot failure: VBS launcher quote-escaping bug. """" in VBS string resolves to "" (empty quote pair), which cmd.exe cancels. Any path with spaces (C:\Program Files\node.exe) breaks instantly and silently - the node process never ran, but the VBS wrapper returned exit code 0 so the task log falsely showed success.
- Abandoned VBS + Scheduled Tasks cascade entirely. Replaced with NSSM (Non-Sucking Service Manager) - one binary wraps any exe into a real Windows service.
- Installed NSSM 2.24 (win64) at C:\Users\user\.milo\nssm.exe (single file, no installer, downloaded from nssm.cc CI build).
- Globally installed @grinev/opencode-telegram-bot via 
pm install -g so the bot doesn't re-download from the internet on every start (was previously using 
px -y @latest which is a silent-failure risk on network hiccups).
- Registered two Windows services via 
ssm install:
  - **MiloServe** - runs opencode.exe serve --port 4096 directly (no node wrapper needed; opencode.exe is a standalone binary)
  - **MiloTelegramBot** - runs 
ode.exe cli.js start against the globally installed bot
- Both services: SERVICE_AUTO_START (boot-triggered, no login needed), AppExit Default Restart (SCM auto-restarts on crash), stdout/stderr to C:\Users\user\.milo\logs\{opencode-serve,milo-telegram-bot}.log
- Critical env var: OPENCODE_TELEGRAM_HOME=C:\Users\user\AppData\Roaming\opencode-telegram-bot injected into MiloTelegramBot via 
ssm set AppEnvironmentExtra - without this the bot service (running as LocalSystem) resolves APPDATA to the SYSTEM profile and can't find .env, causing infinite "Interactive wizard requires a TTY terminal" crash loop
- Replaced the bot's .env template stub (TELEGRAM_BOT_TOKEN=HTTP API:) with the real token so alidateRuntimeEnvValues passes

The OPENCODE_TELEGRAM_HOME env var is the documented escape hatch in the bot source and is the only thing that makes service-mode work.
