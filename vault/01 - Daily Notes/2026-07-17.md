## Session 3 — 12:30-14:00: P1 Browser Control — Browser MCP Setup

### What Got Done
- Diagnosed why CDP-based browser control failed: Opera already running, CDP process is orphaned renderer, profile lock prevents second instance, IPv6/IPv4 mismatch broke Playwright CDP connection.
- Researched alternatives via web search: Browser MCP extension (wins), Playwright MCP sans CDP (general browsing only), opencode-browser-control (auto-detects system browser but still launches clean instance).
- Chose **Browser MCP** (`@browsermcp/mcp@0.1.3`) — hooks into existing browser via Chrome extension. Keeps all Google sessions. No CDP, no separate profile, no scripts.
- Added Browser MCP config to `opencode.jsonc`
- Updated CLAUDE.md: Rule #13 added — "Document as you go, never when reminded"
- Updated Milo Build.md with full P1 documentation: winning method, dead ends to skip, discovery tax paid
- Documentation written for: why CDP failed, why Browser MCP wins, config details

### Key Lessons
- **Browser MCP > CDP for auth flows.** Extension hooks into running browser with all sessions intact. No profile management, no port conflicts, no orphaned processes.
- **CDP is unreliable on Windows with Opera.** Opera's multi-process architecture means CDP processes die independently. Plus IPv6/IPv4 resolution issues with Node.js.
- **Document as you go, not at the end.** Wrote Milo Build.md P1 section as I learned what worked/didn't instead of reconstructing later.
- **Supabase OAuth:** Still pending — Allan clicks "Connect" in Browser MCP extension, then I complete the auth flow via browser tools.

### Decisions Made
- Browser MCP is the canonical browser automation method going forward
- CDP-based approaches (OperaCDP.bat, Playwright --cdp-endpoint, standalone scripts) are deprecated dead ends
- Rule #13: documentation happens in real-time, not on reminder
- Discovery tax is recorded in Milo Build.md under "Dead ends to skip" so no future session pays it
